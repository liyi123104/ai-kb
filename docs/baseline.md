## 3. 判定口径（写清楚，避免以后自欺）

- **召回命中**：Top-5 中存在一条，文件名等于 `expected_source`，且 `expected_page` 落在该条的
  `[page_start, page_end]` 区间内。页码是 PDF 物理页。
- **答案正确**：用 `qwen2.5:7b` 做语义评审（允许跨语言、允许改写，关键事实一致即算对），
  再人工抽检 4 条确认评审没有乱判。计划书原话是「人工标注」，本项目用「模型评审 + 人工抽检」
  替代，这一点在 T4 的结果里有记录，不冒充纯人工。
- **首字延迟**：流式接口从发出请求到第一个 token 到达的时间（模型已加载的热态）。

## 6. 已知问题与处置

| 问题 | 处置 |
|---|---|
| Ollama 版 bge-m3 对个别 token 返回 500 `NaN`（实测 `sequence.` 触发） | 在 `app/llm.py` 的 `SafeOllamaEmbeddings` 里加降级：失败则逐个重试并从尾部逐词缩短（最多砍 1/3），保证检索不整体失败 |
| 目录页 / 参考文献页污染检索 | 切片生成时剔除参考文献类；检索时过滤目录点线与二进制碎片 |
| 7B 模型过度拒答（明明能答却先写「资料中没有」） | 改 prompt：只有确实找不到依据时才允许那句话，并要求第一行直接给答案 |
| 生成被无关上下文带偏 | 生成只用 Top-3（检索指标仍按 Top-5 统计） |
| 首字延迟临界 3 秒 | 冷启动 8.8s、热态 2.7–3.2s；后续在 T3.4/T5 里观察，必要时预热模型 |

## 6.4 拒答稳定性（prompt 四个版本的权衡）

无关问题共 5 条（天气、红烧肉、世界杯、Excel、李白）测试「是否明确说资料中没有」：

| prompt 版本 | 无关问题拒答 | 30 题准确率 |
|---|---|---|
| 原版（只要求资料不足时拒答） | 4/5 | 83.3% |
| 严格版（要求第一行必须原样拒答） | 5/5 | 70.0% |
| 温和版（区分「出现词汇」与「回答问题」） | 5/5 | 76.7% |
| 平衡版 + 纯自然语言要求（当前） | **5/5** | **76.7%** |

拒答与准确率是此消彼长的关系：写得越硬，模型越容易把"资料只沾边"的正常问题也拒掉。
当前版本两者都满足验收（拒答 100%、准确率 ≥70%）。

## 6.5 上下文条数的影响（2026/10/20 补测）

| 喂给模型的上下文条数 | 召回率 | 答案准确率 |
|---|---|---|
| 1 条 | 90.0% | 70.0% |
| **2 条** | **90.0%** | **83.3%** |
| 3 条 | 90.0% | 76.7% |

3 条时反而比 2 条差：多出来的第 3 条往往是"相关性一般"的片段，会把 7B 模型带偏。
默认已改为 2 条（`ANSWER_TOP_N=2`），可用环境变量覆盖。

## 8. 实际服务延迟（2026/10/21 已达标）

计划书 F5 要求「首字 ≤3 秒、完整 ≤15 秒」。**当前本地模式已达标**：

| 场景 | 首字 | 整轮 |
|---|---|---|
| 本地模型热态（5 题实测） | 中位 **1.23s**，最大 1.84s | 中位 2.75s，评测均值 3.6s |
| 云端 DeepSeek 热态（4 题实测） | 0.58–0.86s | 0.87–1.14s |
| 冷启动首次请求（模型加载） | 10–17s | 17–25s |

**根因（花了很久才定位）**：`.env` 里 `OLLAMA_BASE_URL=http://localhost:11434`。
Windows 上 `localhost` 会先解析到 IPv6 `::1`，而 Ollama 只监听 IPv4 `127.0.0.1`，
每次调用先等 IPv6 连接超时再回退，**白付约 2 秒**。这一项同时拖慢了每次嵌入与每次生成，
之前测到的「检索 2.2s + 首 token 5–6s」全部由此而来。

改成 `http://127.0.0.1:11434` 后：嵌入 2.16s → 0.11s，检索 2.18s → 0.2s，首 token → 1.2s。

之前几轮做过的优化仍然有效，保留在代码里：`keep_alive=30m`、启动预热+保活、
向量库客户端单例、`num_ctx=2048`、向量模型按 provider 自动选设备（本地生成时放 CPU
给 qwen 让显存，云端生成时放回 GPU）、云端模式下不再保活本地聊天模型。
