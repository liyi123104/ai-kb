## 2. 三分钟架构讲稿（面试口述版）

> 我的项目是一个本地 RAG 知识库，资料是我自己收集的 10 份 AI 教材和论文，一共 8,895 个切片。

**链路**（按顺序讲，别跳）：
1. **解析**：PDF 用 pypdf 逐页抽取文本，保留物理页码；Word/MD/TXT 各自解析后统一成一页；
2. **切片**：`RecursiveCharacterTextSplitter`，512 字、50 字重叠。这里有个坑 —— LangChain 的
   overlap 是按切分单元整块回退的，PDF 长行会让重叠变成 0，我加了边界补齐，保证「≤512 且相邻重叠 ≥50」；
3. **向量化**：bge-m3（1024 维），走 Ollama 本地推理；
4. **入库**：ChromaDB 本地持久化，余弦距离，用确定性 id 保证重复入库不产生重复数据；
5. **检索**：Top-5，过滤掉目录点线和二进制碎片，再按相似度闸门决定要不要回答；
6. **生成**：qwen2.5:7b，把 Top-3 片段拼进 prompt，要求只依据资料回答、逐句标注 [编号]；
7. **溯源**：跨页切片记 `page_start/page_end`，前端展示「文件 + p.434–435 + 相似度 + 片段」。

**评估**：自建 30 题测试集，覆盖 10 份资料，召回率 90%、准确率 83.3%，基线文档里逐条记了 7 道错题原因。

## 3. 五个必问题的话术

**Q1：你的 RAG 是怎么实现的？**
按上面七步讲；重点强调两处不是照抄教程：切片的 50 字重叠是补出来的；「资料中没有」用
相似度闸门（0.45）+ prompt 双重约束，因为单纯靠阈值不可靠（实测无关文本对余弦也能到 0.35）。

**Q2：怎么评估效果好坏？**
30 题测试集 + 两个指标：检索召回率（正确片段是否进 Top-5，要求同文件且页码落在切片区间）、
答案准确率（语义评审 + 人工抽检，允许跨语言改写）。错题逐条分析写在 `docs/baseline.md`。
不夸大：3 道"未命中"是同文件不同页，严格口径下算未命中，没有放宽。

**Q3：切片大小怎么定的？**
默认 512；做过 A/B：256 = 90.0%、512 = 90.0%、1024 = 86.7%。256 召回持平但索引翻倍、名次更差；
1024 一块混多主题，区分度下降。所以维持 512。

**Q4：为什么用 ChromaDB 不用 ES/Milvus？**
单机、单用户、数据量不到 1 万条，Chroma 零配置、随 Python 进程走、持久化就是一个目录。
数据量到百万级或需要多副本时会换 Milvus / Qdrant，那时才值得付出运维成本。

**Q5：遇到最大的坑是什么？**
Ollama 版 bge-m3 对个别 token 会返回 500 NaN（实测 `sequence.` 触发）：同一句话砍到 12 个词能嵌入，
加上第 13 个词就失败。定位方法是二分截断；修复是在 Embedding 层加降级 —— 失败就逐词缩短重试，
保证用户问一句坏输入不会让整次检索挂掉。这个 bug 也写进了 README 的技术点。

## 4. 技术选型理由一览

| 选型 | 理由 | 什么时候会换 |
|---|---|---|
| FastAPI | 自带 /docs、类型校验、异步流式 | 流量大时加 Gunicorn/Uvicorn workers |
| LangChain | 串联解析/切片/检索/生成的胶水 | 链路稳定后可去掉，直连 OpenAI 兼容接口 |
| ChromaDB | 零配置、本地目录持久化 | 数据量 > 百万或需分布式 |
| bge-m3 | 中文强、1024 维、支持多语 | 英文为主时可换 bge-large / e5-large |
| qwen2.5:7b | 6GB 显存能跑、中文好、免费 | 效果好优先时切 DeepSeek API（一行配置） |
| SQLite | 单文件、零运维、够用 | 多用户并发时换 PostgreSQL |
| Vue3 + Element Plus | 生态成熟、组件全 | 无 |
